接下来我要说的就是这个插件的缺点

我们刚才配置的是“.\$fileNameWithoutExt.exe”意思是根据当前文件名配置exe,但是就会导致在不同的文件上运行时,诞生出来了不同名字的exe,尽管结果一样

​

解决办法就是把$fileNameWithoutExt.exe改成一个具体的名字例如program.exe,这样就不会有这种问题了

最大的缺点就是我们对项目参与的脚本是否全部有用无从得知,一旦混进去无用脚本很难找出来

步骤：项目 -> 属性 -> C/C++ -> 预处理器 -> 预处理定义 -> 编辑 -> 加“_CRT_SECURE_NO_WARNINGS 1”

而在Dev C++和小熊猫C++这种轻量C/C++编译器里分别需要在编译的时候加上这一句,这样控制台输出的中文就不会是乱码了

想必你也发现了—–我们光配置这个环境就浪费了这么多时间,而且可复用性低,而且难以管理文件,每次新开一个项目还都需要我们手动修改配置文件

③ CMake Tools (推荐)

对了,你肯定会注意到CMake Tools下方的CMake插件的存在,emmm,这个是因为以前CMake Tools以前是依赖这个东西的语言服务的,而现在更新了不需要了,可下可不下

我们之前提到的的那个 clangd插件,这里是需要的,这里我们不再依赖gcc,而是使用clang,clang的编译速度大于gcc,而且报错的时候的提示更现代

​

我们先在vscode的设置文件settings.json里把微软的这个智能补全由“default”设置为“disabled”,如果有一天你想要换回方案二就将其设置为default然后禁用 clangd插件

既然你决定使用Clangd插件,那么我们一不做二不休,把Clang也下载了,clang和gcc一样可以运行c或者c++程序

点击前往下载Clang 我们下载后把llvm的bin文件夹添加到系统path路径

​
